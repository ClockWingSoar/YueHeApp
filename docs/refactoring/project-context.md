# YueHeApp 项目上下文和需求记忆

## 项目基本信息

**项目名称**: 悦和国际美容院管理系统 (YueHeApp)  
**项目类型**: 企业级美容院运营管理平台  
**当前状态**: 需要重构和现代化改造  
**负责人**: 小燕 (XiaoYan) - 高级Java开发工程师架构师和SRE  

## 核心需求和要求

### 1. 外观要求
- **简洁大方好用**: 界面设计必须简洁大方，用户体验良好
- **现代化UI**: 采用现代化的用户界面设计
- **响应式设计**: 支持不同设备和屏幕尺寸
- **直观操作**: 操作流程简单直观，减少学习成本

### 2. 性能要求
- **高性能**: 系统必须支持高性能运行
- **快速响应**: 页面加载时间不超过3秒
- **并发支持**: 支持100个并发用户同时使用
- **数据处理**: 支持10万条以上数据记录

### 3. 扩展性要求
- **可扩展**: 系统架构必须支持功能扩展
- **可配置**: 系统参数和功能必须可配置
- **模块化**: 采用模块化设计，便于维护和扩展
- **微服务就绪**: 为未来的微服务架构改造做准备

### 4. 部署要求
- **部署简单**: 部署过程必须简单易行
- **容器化**: 支持Docker容器化部署
- **自动化**: 支持CI/CD自动化部署
- **云原生**: 支持云平台部署

## 技术栈偏好

### 用户建议的技术栈
- **前端**: Next.js + React + Redux
- **后端**: Spring Boot
- **数据库**: MySQL

### 推荐的技术栈
- **前端**: Next.js + React + TypeScript + Ant Design
- **后端**: Spring Boot 3.2+ + Redis
- **数据库**: MySQL 8.0+ + Redis缓存
- **部署**: Docker + Kubernetes

## 业务特点

### 核心业务模块
1. **客户管理**: 客户信息、问卷、档案管理
2. **销售管理**: 销售记录、提成计算、回款管理
3. **操作管理**: 美容操作记录、仪器使用
4. **员工管理**: 员工信息、薪资、职责分配
5. **美容院管理**: 美容院信息、折扣、提成规则
6. **报表管理**: 各类统计报表和数据分析

### 业务复杂度
- **12个核心实体**: 关系复杂，涉及多对多、一对多关系
- **复杂业务规则**: 提成计算、折扣管理、权限控制
- **数据量大**: 支持10万条以上数据记录
- **并发需求**: 支持100个并发用户

## 当前系统问题

### 技术问题
- **技术栈老旧**: Spring Boot 2.1.6，Java 8
- **前端技术落后**: 使用Thymeleaf服务端渲染
- **缺乏类型安全**: 前端无TypeScript支持
- **缓存机制不足**: 缺乏Redis等缓存层
- **监控缺失**: 缺乏性能监控和日志管理

### 用户体验问题
- **界面老旧**: Bootstrap 4.2.1界面过时
- **响应式不足**: 移动端适配不完善
- **交互体验**: 缺乏现代化交互效果
- **加载速度**: 页面加载速度慢

## 重构目标

### 短期目标 (3-6个月)
1. **前端现代化**: 采用Next.js + React + TypeScript
2. **后端升级**: 升级到Spring Boot 3.2+
3. **性能优化**: 添加Redis缓存，优化数据库查询
4. **UI改进**: 采用Ant Design，提升用户体验

### 长期目标 (6-12个月)
1. **微服务改造**: 逐步拆分为微服务架构
2. **云原生**: 完全容器化部署
3. **监控完善**: 建立完整的监控和日志体系
4. **功能扩展**: 添加更多高级功能

## 技术决策原则

### 1. 现代化优先
- 选择最新的稳定版本技术
- 采用现代化的开发模式和最佳实践
- 保持技术栈的先进性和前瞻性

### 2. 性能优先
- 优先考虑系统性能和响应速度
- 采用多层缓存策略
- 优化数据库查询和索引

### 3. 可维护性优先
- 采用模块化设计
- 保持代码的清晰和可读性
- 建立完善的测试体系

### 4. 用户体验优先
- 界面设计简洁大方
- 操作流程简单直观
- 响应速度快，无卡顿
